```text

  ↓
```

# Day 1：先搞清楚 Memory

不要一开始就研究 Zero-Copy。

先建立：

```text
CPU
 ↓
Cache
 ↓
RAM
```

的模型。

例如 Camera：

```text
1920 × 1080
RGB8
```

大小：

```text
1920 × 1080 × 3
≈ 6.2 MB
```

如果：

```text
30 FPS
```

原始数据吞吐量：

```text
6.2 MB × 30
≈ 186 MB/s
```

注意：

> **这还只是原始数据，不包括额外 copy、serialization、deserialization。**

如果系统发生几次复制：

```text
186 MB/s × 4
≈ 744 MB/s
```

这时候内存带宽已经开始成为值得关注的问题。

> **这里到底发生了多少次数据复制？**


# Day 5：Loaned Message

这一天进入 ROS2 的：

> **Loaned Message**

普通方式：

```cpp
auto msg = std::make_unique<MyMsg>();

publisher->publish(std::move(msg));
```

你的思维模型是：

```text
Application owns message
        ↓
publish
        ↓
DDS
```

而 loaned message 的思想是：

```text
DDS / middleware
       ↓
提供一块可直接写入的 buffer
       ↓
Application
       ↓
填充数据
       ↓
publish
```

也就是：

```text
传统：

Application buffer
      ↓ copy
Middleware buffer


Loaned：

Middleware buffer
      ↑
Application directly writes
```

核心目标：

> **减少不必要的数据复制。**

---

# 但是这里有一个非常重要的现实问题

不要把：

> Loaned Message = Zero Copy

画等号。

它们不是完全相同的概念。

Loaned message 更准确地说：

> **允许中间件向应用提供可直接填充/复用的消息存储，从而有机会减少复制和分配。**

是否真正做到：

```text
zero-copy
```

取决于：

```text
RMW
DDS implementation
transport
message type
配置
```

这也是为什么你作为性能优化工程师，不能只看 ROS2 API。

# Day 6：Zero-Copy / SHM

今天进入：

```text
Shared Memory
```

普通跨进程：

```text
Process A
   ↓
serialize
   ↓
kernel / network
   ↓
Process B
   ↓
deserialize
```

共享内存的思路：

```text
Process A
    │
    ▼
Shared Memory
    ▲
    │
Process B
```

数据本身位于：

```text
shared memory region
```

两个进程通过映射访问。

于是可以减少：

```text
copy
```

---

# 但 Zero-Copy 也不是魔法

即使使用共享内存，系统仍然可能存在：

```text
metadata
synchronization
memory allocation
cache coherence
serialization
```

等等成本。

所以真正的问题应该是：

> **这个系统的瓶颈是不是 copy？**

如果不是：

```text
Zero-Copy
```

可能根本不是最优先的优化方向。
