# 2. timestamp 到底表示什么？

这是非常容易混淆的地方。

假设：

```text
t0 = Camera真正曝光
t1 = Driver拿到数据
t2 = ROS2构造message
t3 = Publisher
t4 = DDS发送
t5 = Subscriber收到
t6 = Executor执行callback
```

那么：

```text
t0 ──────────────── t6
│                   │
Camera              callback
capture             start
```

**message 的 timestamp 不一定等于 callback 时间。**

例如：

```cpp
auto msg_time = msg->header.stamp;
auto callback_time = this->now();
```

两者可能差：

```text
callback_time - msg_time
```

这个值才是一个非常重要的：

> **端到端 age / data age**

# TF 真正解决什么？

假设 Camera 数据：

```text
frame_id = camera_link
```

LiDAR：

```text
frame_id = lidar_link
```

算法却需要：

```text
base_link
```

那么：

```text
camera_link
      ↓
    TF2
      ↓
 base_link
```

TF2 给你：

```text
T_base_camera(t)
```

注意这个：

```text
(t)
```

非常重要。

因为 TF **也是带时间的**。

---

# 关键概念

假设：

```text
Camera message timestamp
=
10:00:00.100
```

你查询：

```cpp
lookupTransform(
    "base_link",
    "camera_link",
    msg_time);
```

意思是：

> **我要的是 Camera 在这条数据产生时刻对应的坐标变换。**

而不是：

```cpp
lookupTransform(
    "base_link",
    "camera_link",
    now());
```

后者是：

> 我要当前时刻的 TF。

对于运动中的机器人，两者可能不同。

---

# 这就是“时间同步 + TF”的核心

真正的数据处理链变成：

```text
Camera
   │
   │ timestamp = T1
   ▼
Image
   │
   ├───────────────┐
   │               │
   ▼               ▼
DDS              TF2
   │               │
   │               │ lookup(T1)
   │               ▼
   │          T_base_camera(T1)
   │               │
   └───────┬───────┘
           ▼
       Algorithm
```

这时候你才真正理解：

> **timestamp 不只是用来计算 latency，它还是机器人空间计算的时间索引。**

# 最后建立你的“传感器问题定位树”

以后线上遇到：

> **Camera 延迟 100ms**

不要直接去改 DDS。

按照：

```text
Camera 延迟
│
├── 1. timestamp 是否正确？
│      │
│      ├── 错 → Driver / Sensor clock
│      └── 对
│
├── 2. capture → publish 是否已经慢？
│      │
│      ├── 是 → Driver / preprocessing
│      └── 否
│
├── 3. DDS 是否产生 queue / transport delay？
│      │
│      ├── 是 → QoS / DDS / Network
│      └── 否
│
├── 4. Executor 是否及时执行？
│      │
│      ├── 否 → scheduling / callback blocking
│      └── 是
│
├── 5. TF 是否等待？
│      │
│      ├── 是 → TF buffer / timestamp
│      └── 否
│
└── 6. callback 本身是否慢？
       │
       ├── 是 → CPU / algorithm / memory
       └── 否 → 继续向下排查
```

这张树非常重要。

因为它把你前面几周学的：

```text
CPU
Memory
Thread
Scheduler
DDS
Executor
QoS
```

第一次真正连接到了：

```text
Camera / LiDAR / IMU
```
