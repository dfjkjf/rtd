# With SCHED_FIFO and core pinning

这句话的意思是**结合使用 SCHED_FIFO 调度策略与核心绑定（Core Pinning）技术**。这是一种在操作系统（尤其是 Linux）中用于**极致优化性能、实现极低延迟和确定性响应**的高级系统调优手段，通常用于实时系统、高频交易或高性能网络数据面等对时间极其敏感的场景。

要理解这个概念，我们可以将其拆解为两个部分来看：

### 1. SCHED_FIFO（先进先出实时调度策略）
SCHED_FIFO 是一种实时（Real-Time）调度策略。与默认的普通调度策略（SCHED_OTHER）不同，它具备以下特点：
* **不受时间片限制**：普通线程会被操作系统强制分配时间片并不断切换，而 SCHED_FIFO 线程一旦获得 CPU 控制权，就会一直运行，直到它主动阻塞、退出，或者被更高优先级的实时线程抢占。
* **高优先级**：它的优先级（1-99）永远高于普通线程。这意味着只要 SCHED_FIFO 线程有任务要执行，操作系统会立刻打断普通任务，把 CPU 交给它。
* **适用场景**：适合那些必须在极短时间内完成、不能被打断的“时间敏感型”任务。

### 2. Core Pinning（核心绑定 / CPU 亲和性）
Core Pinning（也叫 CPU Affinity）是一种将特定的软件进程或线程“死死绑定”在指定的物理 CPU 核心上运行的技术。它的核心优势在于：
* **消除上下文切换开销**：如果不绑核，操作系统为了负载均衡，会把线程在不同的核心之间移来移去。每次迁移都需要保存和恢复线程状态，这会消耗大量 CPU 周期。绑核后，线程永远在一个核心上运行，省去了这部分开销。
* **提升缓存命中率（Cache Locality）**：线程一直待在同一个核心上，它之前处理的数据和指令就会一直保留在该核心极快的 L1/L2 缓存中，避免了去较慢的主内存中重新读取数据，从而大幅提升吞吐量并降低延迟。

### 💡 两者结合（With SCHED_FIFO and core pinning）的威力
当把这两者结合起来时，相当于给关键任务开启了**VIP 专属通道**：
* **SCHED_FIFO** 保证了任务在软件层面拥有最高优先级，不会被普通任务打断或排队等待。
* **Core Pinning** 保证了任务在硬件层面拥有专属的计算核心，不会被操作系统挪动，且能最大化利用 CPU 缓存。
