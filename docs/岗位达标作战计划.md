## 〇、核心判断

- **性能优化的对象是 Linux 和通信栈，机器人只是场景**

**里程碑验收**：白板能画出 `publish()` 到 RTPS 报文上网的完整调用链，标注线程边界与内存拷贝点。

---

### 阶段二（第 2-3 个月）：性能工具链体系化

**目标**：JD 列出的每个工具都用真实靶子练过一遍，形成肌肉记忆。

| 工具 | 练习靶子 | 产出 |
|---|---|---|
| top/htop | 日常巡检基线，理解 load/CPU 状态字段 | 监控工具的系统资源采集模块 |
| perf | 给监控工具自己画火焰图，找 CPU 热点 | 一份火焰图分析报告 |
| gdb | 复现并调试一个多线程竞态/崩溃问题 | 调试过程记录 |
| valgrind/ASan | 扫描公司中间件或监控工具的内存问题 | 内存检查报告（您的主场，做出深度） |
| strace | 追一次 Topic 收发涉及的全部系统调用 | 调用序列图 |
| tcpdump | 抓 RTPS 报文，逐包解读（结合协议栈知识） | 报文解读文档——全公司没人比您写得好 |
| dmesg | 排查一次内核层面的异常（OOM/网卡丢包/驱动报错） | 排查案例记录 |
| ftrace | 观察一次调度延迟、跟踪函数调用 | 实验记录 |

**配套阅读**：
- Brendan Gregg《性能之巅》(Systems Performance)：精读方法论章节(USE/RED)
- Brendan Gregg《BPF 性能工具》：eBPF 入门，为 JD 进阶项铺路

**里程碑验收**：给定一台 CPU 跑满的机器，能在 30 分钟内用工具链定位到具体函数热点。

---

### 阶段三（第 3-4 个月）：Linux 内核原理补课

**目标**：把经验层面的理解升级为内核级体系，面试深挖不慌。

**三块硬骨头**：

1. **进程/线程调度**
   - CFS 原理、vruntime、抢占
   - 实时调度策略 SCHED_FIFO/SCHED_RR（机器人系统必用，重点）
   - CPU 亲和性、isolcpus、NUMA
   - 实验：写个 SCHED_FIFO 实时线程，用 ftrace 观察调度行为

2. **内存**
   - 虚拟内存、缺页、页缓存、SLAB
   - malloc 实现(glibc/ptmalloc)、内存碎片
   - 实验：写个内存泄漏 demo，用 perf/valgrind 分别定位，对比手段

3. **网络 I/O**
   - 收包路径：网卡→中断→软中断(NAPI)→协议栈→socket
   - epoll/select 机制、零拷贝(sendfile/MMAP)
   - 实验：用 perf 追一次 UDP 收包的完整内核路径

**书目**：
- 《Linux 内核设计与实现》(Robert Love)：主线读物
- 《深入理解 Linux 内核》：按需查阅
- 原则：**每个知识点必须配一个实验验证，拒绝纯读书**

**里程碑验收**：能完整讲清"一个 UDP 包从网卡到用户态回调"经过的全部环节及每处的性能开销。

---

### 阶段四（第 4-5 个月）：机器人领域渗透

**目标**：把加分项(SLAM/导航/控制/硬件集成)从空白变成实战经历。

- [ ] 读公司 SLAM/导航/控制模块代码，画完整数据流图：
      传感器 → SLAM/定位 → 规划 → 控制 → 执行，标注每段的 Topic、消息类型、延迟预算
- [ ] 学习 Nav2 导航栈架构（文档 + 架构图级别即可，不必深入算法）
- [ ] SLAM 概念扫盲：前端/后端/回环检测，看懂 ORB-SLAM 类架构图即可
- [ ] 主动找算法团队搭伙：他们的"卡顿、延迟抖动"问题往往根因在通信层
      ——这是您的切入点，也是 JD"跨团队协作"的实战素材
- [ ] 争取参与一次硬件联调（传感器驱动 ↔ 中间件），把"硬件集成"经验拿到手
- [ ] 完成监控工具 v0.3：延迟监测 + 系统资源采集 + 告警规则

**里程碑验收**：与算法/控制团队完成一次联合排障，产出问题定位报告。

### 阶段五（第 6 个月）：成果固化

- [ ] 简历按该 JD 重写：技能清单逐条对标 JD 关键词，每个案例带数字

**里程碑验收**：用新版简历对照 JD 逐条自检——每条要求都能指着一个案例说"我做过"。

3. ✅ 简历上有 3 个量化案例，覆盖 CPU/内存/网络三类问题
4. ✅ 能和一个 SLAM 或导航团队完成一次联合排障
